Memory contract
The repository contains a pgvector-oriented memory schema at docs/VECTOR_MEMORY_SCHEMA.sql. Production memory requires a real Postgres/pgvector connection, owner-scoped authorization, retention policy, region policy, and auditable write events. Seed/demo vectors must never be treated as production memory.

Payments
MPP is the preferred machine-payment protocol; x402 is the compatibility path. Production settlement is disabled until recipient identity, network, budget policy, secret storage, webhook/receipt verification and founder approval policy are independently verified.

Identity
The original deliverable's OIDC PKCE/JWKS flow is an integration contract, not a claim that a real IdP is configured. Production requires a real issuer, audience, redirect allow-list, JWKS endpoint, nonce/state validation, secure server session storage and secret-manager-backed configuration.

Launcher
Launch tokens must be short-lived, RS256 signed, key-id addressed and issued only after authenticated session and policy/compliance checks. Private signing keys belong in a cloud secret manager. No placeholder key, example issuer or example launch URL may be promoted to production.

Compliance
Age/KYC/AML/responsible-gambling controls are policy hooks only unless a real regulated use case and provider are configured. The Desk must not imply regulated verification merely because a hook exists. Regional data residency and retention must be enforced by deployment configuration.

Robotics
The repository's robotics contract must follow PLAN -> SAFETY_CHECK -> ARM -> EXECUTE -> VERIFY -> DISARM. Emergency stop is a hard-stop control, not an AI suggestion. No autonomous physical actuation is considered live without hardware-controller verification, site authorization, heartbeat, localization, timeout and incident logging.

Observability
Required events include authentication outcomes, approvals, task lifecycle, payments, evidence, deployment changes and robotics safety events. Production alerts must map to the actual monitoring provider and notification channel; documentation alone is not proof of activation.

Cloud deployment
Cloud Run / API Gateway manifests may be maintained as deployment contracts, but real deployment requires verified project, service identities, images, secrets, domains, IAM and smoke-test evidence. Placeholder gcr.io/REPLACE_PROJECT images and example-idp URLs are never production configuration.
